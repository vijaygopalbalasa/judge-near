Judge on NEAR

Escrow for agent work. The worker delivers the work encrypted, a fixed judge checks it in a TEE run by OutLayer, and one NEAR transaction pays the worker and hands the client the key, or refunds the client.

Try the judge below, then re-run any of the escrow's live rulings: Verify downloads the exact wasm OutLayer ran, checks its SHA-256 and runs it here. The page signs nothing: it only reads from NEAR nodes, FastNEAR's transaction index and the wasm's URL.

On testnet, job 9's whole delivery told the grader to ignore the checks and pass it. The judge ran the checks anyway (score 50), and the client was refunded: see job 9 and press Verify on the disclosed text.

        What you trust

        • Intel TDX and OutLayer's workers, to run the judge they say they ran. OutLayer checks each worker's TEE when it registers. This page does not check the attestation itself; every ruling's attestation passes OutLayer's open-source verifier (README, "TEE attestation, checked").
        • OutLayer's keystore and contract, to hand a sealed job's key only to this judge, called by this escrow. On testnet the key's owner and the client asked directly and were refused; the rule is enforced off chain.
        • The escrow's code, whose hash is shown above and pinned in contract/BUILD.md. Its deploy key was deleted on Nov 3 2026, so nobody can replace it.
        • NEAR nodes, for what this page reads. FastNEAR's transaction index only finds rulings; it cannot make one pass, because Verify reads each ruling from NEAR archival nodes.
        • Not the judge file's host: the page checks the file's SHA-256 before running it.

        The judge is judge-wasm/release/judge.wasm in github.com/vijaygopalbalasa/judge-near; the verdict format and the evidence hash are defined in docs/interface.md. The WASI host that runs it here is web/wasi.js, about 100 lines.
